# 出張報告書作成アシスタント 設計書

## 1. システム概要

### 1.1 目的
- 報告書作成の品質を均一化し、必要な情報を漏れなく収集
- 報告書作成が苦手な人（若手・外国人スタッフ）でも高品質な報告書を作成可能に
- 楽しく報告書を作成できる仕組みを提供

### 1.2 ターゲットユーザー
- 若手社員（報告書作成に不慣れな方）
- 外国人スタッフ（日本語での文章作成に課題がある方）
- 報告書作成が苦手な全ての社員

## 2. 機能要件

### 2.1 基本情報入力機能

#### 2.1.1 入力項目
| 項目 | 必須/任意 | 備考 |
|------|----------|------|
| 出張者氏名 | 必須 | |
| 社員ID | 必須 | |
| 部署名 | 必須 | |
| 出張日時 | 必須 | 開始日・終了日 |
| 出張先 | 必須 | 都道府県・市区町村・訪問先企業名 |

#### 2.1.2 データ取り込み機能（将来実装）
- 出張申請書からの自動取り込み
- 社員マスタとの連携
- 経費精算システムとの連携

### 2.2 対話型インタビュー機能

#### 2.2.1 キャラクター設定
複数のキャラクターを用意し、ユーザーが選択可能

**キャラクター案：**

1. **ますお兄さん（50代ベテラン営業マン）**
   - 口調：「そんがんこつはどうやったがけ？」「なるほどのう」
   - 性格：温厚で聞き上手、経験豊富
   - 役割：メインインタビュアー

2. **あやちゃん（20代若手企画職）**
   - 口調：「それってどういうことながけ？」「すごいじゃん！」
   - 性格：明るく好奇心旺盛
   - 役割：掘り下げ質問、共感役

3. **けんじ部長（40代管理職）**
   - 口調：「そこは大事ながいぜ」「で、結果はどうやった？」
   - 性格：要点を押さえる、実務的
   - 役割：成果・課題の確認

#### 2.2.2 インタビュー形式
**ポッドキャスト風の会話進行：**

```
[開始]
ますお：「お疲れさまでした！今日は○○への出張やったがいね。どんな感じやった？」

[ユーザー回答]

あやちゃん：「へぇ〜！それで、一番印象に残ったことは何ながけ？」

[ユーザー回答]

けんじ部長：「なるほどのう。で、当初の目的は達成できたがけ？」
```

#### 2.2.3 質問項目（段階的深掘り）

**Phase 1: アイスブレイク**
- 出張全体の印象
- 天気や移動の様子など

**Phase 2: 目的の確認**
- 今回の出張の目的は何だったか
- 誰と会ったか
- 何を話し合ったか

**Phase 3: 成果の深掘り**
- 具体的に得られた成果
- 数値的な結果（あれば）
- 新しい発見や気づき

**Phase 4: 課題・問題の抽出**
- うまくいかなかったこと
- 改善が必要なポイント
- 今後の懸念事項

**Phase 5: 今後のアクション**
- 次にやるべきこと
- 期限や担当者
- 社内への共有事項

#### 2.2.4 対話制御ロジック

```
IF ユーザー回答が短い（20文字以下）THEN
  「もうちょっと詳しく教えてくれんけ？」と追加質問

IF 重要キーワード（課題、問題、失敗）が出現 THEN
  原因分析の質問を追加
  
IF 成果が曖昧 THEN
  具体的な数値や事例を確認

質問回数 < 15回 で必要情報が揃ったら終了を提案
```

### 2.3 報告書生成機能

#### 2.3.1 出力フォーマット

```
================================
出張報告書
================================

【基本情報】
報告者：[氏名]（[部署]）
社員ID：[ID]
出張期間：[開始日] 〜 [終了日]
出張先：[都道府県][市区町村] [訪問先]
同行者：[氏名]

【出張目的】
[150〜300文字で目的を記載]

【活動内容】
[訪問先での活動を時系列または項目別に記載]
- [内容1]
- [内容2]

【成果・収穫】
[具体的な成果を記載]
1. [成果1]（可能な限り数値化）
2. [成果2]

【課題・問題点】
[発生した課題とその原因分析]
■ 課題：[課題内容]
  原因：[分析結果]
  
【今後のアクション】
□ [アクション1]（期限：[日付]、担当：[氏名]）
□ [アクション2]（期限：[日付]、担当：[氏名]）

【所感】
[報告者の気づきや提案など]

以上
```

#### 2.3.2 文章生成ルール
- 対話内容から自然な日本語文章を生成
- 箇条書きと文章を適切に使い分け
- 冗長な表現を避け、簡潔にまとめる
- 重要な情報は太字や下線で強調（オプション）

### 2.4 編集機能

#### 2.4.1 セクション別編集
- 各セクション（目的、活動内容、成果など）ごとに個別編集可能
- リアルタイムプレビュー表示

#### 2.4.2 追加・削除
- セクションの追加・削除
- 箇条書き項目の追加・削除
- 自由記述欄の追加

#### 2.4.3 再生成機能
- 「この部分をもっと詳しく」ボタン
- 「もっと簡潔に」ボタン
- トーン変更（丁寧・カジュアル・簡潔）

## 3. 非機能要件

### 3.1 ユーザビリティ
- スマートフォンでも操作可能なレスポンシブデザイン
- 音声入力対応（将来実装）
- 平均10分以内で報告書完成

### 3.2 パフォーマンス
- チャット応答時間：3秒以内
- 報告書生成時間：5秒以内
- 同時接続ユーザー数：100名以上

### 3.3 セキュリティ
- 社員認証（SSO連携）
- 下書き自動保存（3分ごと）
- アクセスログの記録

### 3.4 多言語対応
- 日本語・英語・中国語での対話対応
- 最終報告書は日本語で統一

## 4. システム構成

### 4.1 技術スタック案

```
[フロントエンド]
- React / Next.js
- Tailwind CSS
- shadcn/ui（UIコンポーネント）

[バックエンド]
- Node.js / Python（FastAPI）
- OpenAI API / Claude API（対話エンジン）
- PostgreSQL（データ保存）

[インフラ]
- AWS / Azure
- Docker
- CI/CD（GitHub Actions）
```

### 4.2 データフロー

```
1. ユーザーログイン → 社員情報取得
2. 基本情報入力 → DB保存（下書き）
3. キャラクター選択 → セッション開始
4. 対話ループ
   - ユーザー入力 → AI処理 → 応答生成
   - 回答内容をJSON形式で蓄積
5. 対話完了 → 報告書生成
6. 編集 → 最終確認
7. 提出 → PDF出力 & DB保存
```

## 8. KPI設定

### 8.1 定量指標
- 報告書作成時間：平均30分 → 10分以下
- 報告書の文字数：平均800文字以上
- ユーザー満足度：4.0/5.0以上
- 月間利用率：80%以上

### 8.2 定性指標
- 報告書の質の均一化
- 必須情報の記載漏れゼロ
- 外国人スタッフの報告書品質向上

---

## 9. リスクと対策

| リスク | 影響 | 対策 |
|--------|------|------|
| AIが不適切な応答を生成 | 中 | プロンプトエンジニアリング、応答フィルタリング |
| ユーザーが対話を途中で離脱 | 中 | 自動保存、再開機能 |
| 富山弁の理解が難しい | 低 | 標準語モードも用意、方言解説機能 |
| 個人情報の漏洩 | 高 | 暗号化、アクセス制御、監査ログ |

---

## 10. 成功の定義

1. **業務効率化**：報告書作成時間が50%以上削減
2. **品質向上**：報告書の情報充実度が平均30%向上
3. **利用定着**：3ヶ月後の継続利用率70%以上
4. **満足度**：「報告書作成が楽になった」と回答する人が80%以上

## 補足：富山弁フレーズ集

- 「そんがんこつはどうやったがけ？」（そういうことはどうだったの？）
- 「なーん、すごいじゃ！」（えー、すごいね！）
- 「もうちょっと詳しく教えてくれんけ？」（もう少し詳しく教えてくれない？）
- 「そこは大事ながいぜ」（そこは大事だよね）
- 「なるほどのう」（なるほどね）
- 「ほんなら、次は〜」（それでは、次は〜）
